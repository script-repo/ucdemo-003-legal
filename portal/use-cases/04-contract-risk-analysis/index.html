Contract Risk Analysis

What This Does

Contract Risk Analysis takes an uploaded contract and produces a comprehensive risk assessment in seconds. The AI reads the full document, scores overall risk on a 1–100 scale, breaks down risk by category (financial, operational, compliance, legal, reputational), identifies specific high-risk clauses, flags regulatory commitments with deadlines, and generates prioritized recommended actions — all presented as an interactive risk dashboard.

Instead of spending hours manually reviewing a contract for hidden liabilities, a risk officer uploads the document, selects which risk categories to analyze, and receives a structured report with severity ratings, clause-level detail, and actionable next steps. All processing runs on-premises via Nutanix AI, so sensitive contract data never leaves the firm's infrastructure.

Data Flow Summary

  1. User uploads a contract document (TXT, PDF, DOCX) or pastes contract text via the Portal UI.
  2. User selects risk taxonomy categories (Financial, Operational, Compliance, Legal, Reputational) and clicks "Analyze Risk."
  3. The browser extracts the text content and sends it to the API Proxy.
  4. The API Proxy forwards the request (with authentication) to the NAI chat completions endpoint.
  5. NAI analyzes the contract and returns a structured JSON response with risk scores, category heat map, clause risks, regulatory commitments, and recommended actions.
  6. The Portal UI renders the risk dashboard: overall score, heat map grid, clause risk cards, regulatory commitments table, and action items.
  7. Contract metadata is saved to PostgreSQL for audit and history tracking.
  8. Clause embeddings are stored in ChromaDB for future RAG-powered risk taxonomy matching.

Architecture Overview

How It Works

Platform Infrastructure

The entire solution runs on Nutanix AHV, a secure enterprise-grade hypervisor that provides the virtualization layer for all compute, storage, and networking. On top of AHV, NKP (Nutanix Kubernetes Platform) provisions and manages the Kubernetes environment, providing container orchestration, auto-scaling, service discovery, and lifecycle management for all application workloads.

Kubernetes Workloads (db-project-003 namespace)

All use-case components are deployed as pods within the db-project-003 Kubernetes namespace:

  • Portal UI — A lightweight static front-end (HTML, CSS, JavaScript) that provides the contract upload interface, risk taxonomy selector, architecture visualization, and risk dashboard display. Served by a Python-based development server that also acts as the API proxy.
  • API Proxy (server.py) — A server-side CORS proxy that routes browser requests to the Nutanix AI endpoints. Because the NAI inference service does not return browser CORS headers, all /api/ai/* requests are forwarded server-side with the bearer token injected, eliminating cross-origin restrictions.
  • PostgreSQL (pg-db) — A relational database that stores contract metadata, risk analysis results, audit logs, and user activity. Exposed internally via ClusterIP on port 5432. Data is persisted on a Nutanix Volumes PVC (20 GiB) to ensure durability across pod restarts and rescheduling.
  • ChromaDB (ch-db) — An open-source vector database used as the RAG store for clause embeddings. Contract clauses are vectorized using the NAI embedding model (llama-3-2-embed) and stored in ChromaDB for semantic search against the firm's risk taxonomy. This enables clause-level risk matching and category classification. Exposed internally via ClusterIP on port 8000 with its own Nutanix Volumes PVC (20 GiB).
  • Ingress / LoadBalancer Service — External traffic is routed into the cluster via a Kubernetes LoadBalancer service, providing a stable IP address for browser access without requiring DNS configuration.

AI & Inference (Nutanix AI — NAI)

Nutanix AI (NAI) provides the enterprise inference endpoints that power the contract risk analysis:

  • Chat Completions (llama3-1-8b) — The primary LLM endpoint for risk analysis. When a contract is uploaded, the full text is sent along with a structured system prompt that instructs the model to return a JSON object containing the overall risk score (1–100), risk level (Low/Medium/High), category scores (financial, operational, compliance, legal, reputational), clause-level risks with severity and recommended actions, regulatory commitments with deadlines, and prioritized recommended actions. The model performs legal reasoning to identify risks across the selected taxonomy categories and generates actionable recommendations for the risk officer.
  • Embeddings (llama-3-2-embed) — The embedding model vectorizes contract clauses and risk taxonomy terms into high-dimensional vectors. These vectors are stored in ChromaDB and used for semantic search—enabling the risk analysis pipeline to match clauses against the firm's risk taxonomy and retrieve relevant precedent for scoring and fallback language suggestions.

Risk Analysis Pipeline

The risk analysis pipeline works as follows:

  1. Contract Ingestion — The user uploads a contract (TXT, PDF, DOCX) or pastes text via the Portal UI. The browser extracts text content and sends it to the API Proxy.
  2. Clause Embedding (optional) — For enhanced analysis, clause text can be sent to the NAI embedding endpoint (llama-3-2-embed) to vectorize clauses for similarity search against ChromaDB's risk taxonomy collection.
  3. Vector Search (optional) — Retrieved clause embeddings from ChromaDB provide context for risk category mapping and precedent-based scoring.
  4. LLM Risk Analysis — The contract text, selected risk categories (financial, operational, compliance, legal, reputational), and system prompt are sent to the NAI chat completions endpoint (llama3-1-8b), which produces the risk dashboard: overall score, category heat map, clause risks, regulatory commitments, and recommended actions.
  5. Results & Persistence — The Portal UI renders the risk dashboard. Contract metadata and analysis results are saved to PostgreSQL for audit and history tracking.

Storage Layer

  • Nutanix Unified Storage — Serves as the model repository for NAI, hosting the LLM weights, tokenizer configurations, and model artifacts for both the chat completions model (llama3-1-8b) and the embedding model (llama-3-2-embed). This ensures model data resides on-prem with enterprise-grade data protection, deduplication, and replication.
  • Nutanix Volumes — Provides persistent block storage for the Kubernetes PVCs backing PostgreSQL and ChromaDB. Volumes ensures data durability, snapshots, and consistent performance for database workloads running as containerized pods on NKP.
