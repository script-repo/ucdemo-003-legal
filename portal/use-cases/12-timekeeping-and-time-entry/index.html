Timekeeping & Time Entry

What This Does

Timekeeping & Time Entry uses AI to convert a free-form description of an attorney’s daily activities into structured, billable time entries. Instead of manually reconstructing hours from notes or memory, attorneys describe what they did in plain language. The AI parses the description, assigns appropriate matter codes, phase/task codes, durations, and billable status, producing a ready-to-submit time entry table that complies with firm billing standards.

Enter the date, attorney name, matter/client, and a narrative of activities (e.g., “Reviewed deposition transcript for 2 hours, drafted motion for summary judgment, 30-minute client call”). The system returns a daily summary with total hours, a table of individual entries with matter, phase, task code, description, duration, and billable flag, plus any warnings (e.g., total hours exceeding 24, missing matter assignments).

Example User Journey

1
Enter Date & Activities

An attorney selects the work date, enters their name and matter, then describes the day’s activities in plain language (e.g., “Drafted discovery responses, 1.5 hrs; client call re settlement, 45 min”).

2
AI Analyzes

The system sends the description to the Nutanix AI inference endpoint, which parses activities and maps them to matter codes, phase/task codes, and durations.

3
Review Generated Entries

A daily summary shows total hours. The time entries table displays each activity with matter, phase/task, description, duration, and billable status. Warnings highlight potential issues.

4
Submit or Edit

The attorney reviews the entries, edits if needed, and submits to the firm’s billing system. Results are saved for history and audit.

Data Flow Summary

  1. User enters date, attorney name, matter/client, and activity description in the Portal UI.
  2. The form data is sent to the API Proxy, which forwards it to the NAI chat completions endpoint.
  3. NAI parses the activities and returns structured JSON: totalHours, entries array (matter, phase, taskCode, description, duration, billable), summary, and warnings.
  4. The Portal UI renders the daily summary, time entries table, and warnings.
  5. Results are persisted to PostgreSQL for history and audit tracking.

Architecture Overview

How It Works

Form-Based Input

The Portal UI presents a simple form: date picker, attorney name, matter/client, and a textarea for activity descriptions. No document upload is required. The attorney describes work in natural language (e.g., “Drafted motion for 2 hours, client call 45 min, research on case law 1.5 hrs”).

AI Parsing

The Nutanix AI chat completions endpoint receives the structured prompt (date, attorney, matter, activities) and returns a JSON object with totalHours, an entries array (each with matter, phase, taskCode, description, duration, billable), a brief summary, and a warnings array for potential issues.

Results & Persistence

The UI displays the daily total, a table of time entries, and any warnings. Results are saved to PostgreSQL via the /api/db/summaries endpoint for history and audit. Recent submissions appear in the sidebar for quick recall.
