Litigation Strategy

What This Does

Litigation Strategy & Predictive Analytics uses AI to analyze case details and predict outcomes. Enter the case type, jurisdiction, description, key facts, opposing counsel notes, and desired outcome. The AI produces a structured strategy with win probability, strategic recommendations, risk factors, timeline milestones, and estimated costs. This supports client counseling, settlement decisions, and internal resource planning.

The system does not replace attorney judgment. It provides data-driven insights to inform strategy discussions and set realistic client expectations.

Example User Journey

1
Enter Case Details

Select case type (Commercial, Employment, IP, Personal Injury, Class Action, or Antitrust), jurisdiction, and provide a case description, key facts, opposing counsel notes, and desired outcome.

2
AI Analyzes

The system sends the case details to the Nutanix AI inference endpoint, which analyzes facts, researches precedents, and predicts outcomes.

3
Review Results

A win probability (1–100) and confidence level appear. Strategic recommendations, risk factors, timeline milestones, and estimated costs are displayed in a structured format.

4
Use in Strategy

The attorney uses the output in strategy and client discussions. Results inform settlement ranges, key success factors, and resource allocation—without substituting for professional judgment.

Data Flow Summary

  1. User enters case details via the form (case type, jurisdiction, description, key facts, opposing counsel, desired outcome).
  2. The browser sends the form data to the API Proxy.
  3. The API Proxy forwards the request (with authentication) to the NAI chat completions endpoint.
  4. NAI analyzes the case and returns a structured JSON response with win probability, strategies, risk factors, timeline, and estimated costs.
  5. The Portal UI renders the results: probability badge, summary, strategy cards, risk factors table, and timeline milestones.
  6. Analysis metadata is saved to PostgreSQL for audit and history tracking.

Architecture Overview

How It Works

Platform Infrastructure

The entire solution runs on Nutanix AHV, a secure enterprise-grade hypervisor that provides the virtualization layer for all compute, storage, and networking. On top of AHV, NKP (Nutanix Kubernetes Platform) provisions and manages the Kubernetes environment, providing container orchestration, auto-scaling, service discovery, and lifecycle management for all application workloads.

Kubernetes Workloads (ntnx-use-cases namespace)

All use-case components are deployed as pods within the ntnx-use-cases Kubernetes namespace:

  • Portal UI — A lightweight static front-end (HTML, CSS, JavaScript) that provides the case entry form, architecture visualization, and strategy results display. Served by a Python-based development server that also acts as the API proxy.
  • API Proxy (server.py) — A server-side CORS proxy that routes browser requests to the Nutanix AI endpoints. Because the NAI inference service does not return browser CORS headers, all /api/ai/* requests are forwarded server-side with the bearer token injected, eliminating cross-origin restrictions.
  • PostgreSQL 16 (pg-db) — A relational database that stores analysis metadata, audit logs, and user activity. Exposed internally via ClusterIP on port 5432. Data is persisted on a Nutanix Volumes PVC (20 GiB) to ensure durability across pod restarts and rescheduling.
  • ChromaDB (ch-db) — An open-source vector database used as the RAG (Retrieval-Augmented Generation) store for clause embeddings. Exposed internally via ClusterIP on port 8000 with its own Nutanix Volumes PVC (20 GiB).
  • Ingress / LoadBalancer Service — External traffic is routed into the cluster via a Kubernetes LoadBalancer service, providing a stable IP address for browser access without requiring DNS configuration.

AI & Inference (Nutanix AI — NAI)

Nutanix AI (NAI) provides the enterprise inference endpoints that power the litigation strategy analysis:

  • Chat Completions (llama3-1-8b) — The primary LLM endpoint. When case details are submitted, the form data is sent along with a structured system prompt that instructs the model to return a JSON object containing win probability, confidence level, summary, strategies, risk factors, timeline, and estimated costs. The model performs legal reasoning to predict outcomes and recommend strategies.

Storage Layer

  • Nutanix Unified Storage — Serves as the model repository for NAI, hosting the LLM weights, tokenizer configurations, and model artifacts.
  • Nutanix Volumes — Provides persistent block storage for the Kubernetes PVCs backing PostgreSQL and ChromaDB.
