Knowledge Management

What This Does

Knowledge Management searches the firm's internal precedent library — memos, briefs, templates, opinions, and contracts — to surface the best examples for your matter. Instead of manually digging through shared drives or document management systems, an attorney describes what they need (e.g., "indemnity clause for tech M&A") and receives ranked precedents with summaries, relevance scores, and key excerpts in seconds.

The AI searches and summarizes firm work product, improving quality and consistency and accelerating training of junior attorneys. Results include document type, practice area, author, date, and a relevance score so you can quickly identify the most useful precedent to adapt.

Example User Journey

1
Describe Your Need

An associate needs precedent for an indemnity clause in a tech M&A deal. She types her search query and optionally filters by document type (e.g., Contracts) and practice area (e.g., M&A).

2
AI Searches Knowledge Base

The system sends the query to the Nutanix AI inference endpoint, which searches and reasons over the firm's precedent corpus. The AI returns a structured response with ranked precedents.

3
Review Precedents

Results appear as precedent cards: title, document type, practice area, author, date, relevance score, key excerpt, and takeaway. Each card helps the attorney quickly assess fit for the matter.

4
Refine & Adapt

The system suggests follow-up searches. The associate clicks one to deepen the search — building a complete set of precedents in minutes instead of hours. Usage is logged for future relevance.

Data Flow Summary

  1. Attorney enters a search query via the Portal UI and optionally selects document type and practice area filters.
  2. The browser sends the query and filters to the API Proxy.
  3. The API Proxy forwards the request (with authentication) to the NAI chat completions endpoint.
  4. NAI searches and summarizes firm precedents, returning a structured JSON response with summary, precedents, and suggested follow-up searches.
  5. The Portal UI renders the results: summary, precedent cards with relevance bars, and follow-up chips.
  6. Search history is saved to PostgreSQL for audit and history tracking.

Architecture Overview

How It Works

Platform Infrastructure

The entire solution runs on Nutanix AHV, a secure enterprise-grade hypervisor that provides the virtualization layer for all compute, storage, and networking. On top of AHV, NKP (Nutanix Kubernetes Platform) provisions and manages the Kubernetes environment, providing container orchestration, auto-scaling, service discovery, and lifecycle management for all application workloads.

Kubernetes Workloads (db-project-003 namespace)

All use-case components are deployed as pods within the db-project-003 Kubernetes namespace:

  • Portal UI — A lightweight static front-end (HTML, CSS, JavaScript) that provides the precedent search interface, architecture visualization, and results display. Served by a Python-based development server that also acts as the API proxy.
  • API Proxy (server.py) — A server-side CORS proxy that routes browser requests to the Nutanix AI endpoints. All /api/ai/* requests are forwarded server-side with the bearer token injected, eliminating cross-origin restrictions.
  • PostgreSQL 16 (pg-db) — A relational database that stores search history, audit logs, and user activity. Exposed internally via ClusterIP on port 5432. Data is persisted on a Nutanix Volumes PVC (20 GiB).
  • ChromaDB (ch-db) — An open-source vector database used as the RAG store for precedent embeddings. Firm work product is vectorized using the NAI embedding model and stored in ChromaDB for fast semantic search.
  • Ingress / LoadBalancer Service — External traffic is routed into the cluster via a Kubernetes LoadBalancer service.

AI & Inference (Nutanix AI — NAI)

Nutanix AI (NAI) provides the enterprise inference endpoints that power precedent search:

  • Chat Completions (llama3-1-8b) — The primary LLM endpoint. When an attorney enters a search query, the query (and optional filters) is sent to the chat completions endpoint. The model searches and summarizes firm precedents, returning a structured JSON with summary, ranked precedents (title, documentType, practiceArea, author, date, relevanceScore, excerpt, keyTakeaway), and suggested follow-up searches.
  • Embeddings (llama-3-2-embed) — The embedding model vectorizes precedent documents and user queries for semantic search in ChromaDB.

Storage Layer

  • Nutanix Unified Storage — Serves as the model repository for NAI, hosting the LLM weights and model artifacts.
  • Nutanix Volumes — Provides persistent block storage for the Kubernetes PVCs backing PostgreSQL and ChromaDB.
