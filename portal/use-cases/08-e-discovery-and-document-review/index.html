E-Discovery & Document Review

Architecture Overview

How It Works

Platform Infrastructure

The entire solution runs on Nutanix AHV, a secure enterprise-grade hypervisor that provides the virtualization layer for all compute, storage, and networking. On top of AHV, NKP (Nutanix Kubernetes Platform) provisions and manages the Kubernetes environment, providing container orchestration, auto-scaling, service discovery, and lifecycle management for all application workloads.

Kubernetes Workloads (ntnx-use-cases namespace)

All use-case components are deployed as pods within the ntnx-use-cases Kubernetes namespace:

  • Portal UI — A lightweight static front-end (HTML, CSS, JavaScript) that provides the document upload interface, matter context input, review scope selection, architecture visualization, and e-discovery results display. Served by a Python-based development server that also acts as the API proxy.
  • API Proxy (server.py) — A server-side CORS proxy that routes browser requests to the Nutanix AI endpoints. Because the NAI inference service does not return browser CORS headers, all /api/ai/* requests are forwarded server-side with the bearer token injected, eliminating cross-origin restrictions.
  • PostgreSQL 16 (pg-db) — A relational database that stores review metadata, document classifications, audit logs, and user activity. Exposed internally via ClusterIP on port 5432. Data is persisted on a Nutanix Volumes PVC (20 GiB) to ensure durability across pod restarts and rescheduling.
  • ChromaDB (ch-db) — An open-source vector database used as the RAG store for document embeddings. Document chunks are vectorized using the NAI embedding model (llama-3-2-embed) and stored in ChromaDB for conceptual search and clustering. Exposed internally via ClusterIP on port 8000 with its own Nutanix Volumes PVC (20 GiB).
  • Ingress / LoadBalancer Service — External traffic is routed into the cluster via a Kubernetes LoadBalancer service, providing a stable IP address for browser access without requiring DNS configuration.

AI & Inference (Nutanix AI — NAI)

Nutanix AI (NAI) provides the enterprise inference endpoints that power the e-discovery document review:

  • Chat Completions (llama3-1-8b) — The primary LLM endpoint. When documents are uploaded, the text is sent along with matter context and review scope. The model returns structured JSON containing document classification (responsive/non-responsive/privileged), relevance scoring, privilege analysis, key themes, entity extraction, summaries, and recommended actions (Produce/Withhold/Further Review) for deposition and trial prep.
  • Embeddings (llama-3-2-embed) — The embedding model vectorizes document chunks and queries into high-dimensional vectors. These vectors are stored in ChromaDB and used for conceptual search and clustering—enabling the TAR (Technology-Assisted Review) pipeline to find semantically similar documents and support prioritization workflows.

TAR/RAG Pipeline

The Technology-Assisted Review and Retrieval-Augmented Generation pipeline works as follows:

  1. Document Embedding — Document text is chunked and sent to the NAI embedding endpoint (llama-3-2-embed), which returns vector representations for conceptual search and clustering.
  2. Vector Search — The embedding vectors are stored in ChromaDB and queried for similarity matching, enabling prioritization of likely-responsive documents and thematic clustering.
  3. Context Assembly — Retrieved document chunks and metadata are assembled as context for the LLM.
  4. LLM Classification & Summarization — The document text, matter context, and system prompt are sent to the NAI chat completions endpoint (llama3-1-8b), which produces the classification, relevance score, privilege analysis, themes, summaries, and recommended actions.

Storage Layer

  • Nutanix Unified Storage — Serves as the model repository for NAI, hosting the LLM weights, tokenizer configurations, and model artifacts for both the chat completions model (llama3-1-8b) and the embedding model (llama-3-2-embed). This ensures model data resides on-prem with enterprise-grade data protection, deduplication, and replication.
  • Nutanix Volumes — Provides persistent block storage for the Kubernetes PVCs backing PostgreSQL and ChromaDB. Volumes ensures data durability, snapshots, and consistent performance for database workloads running as containerized pods on NKP.

Data Flow Summary

  1. User uploads documents (TXT, PDF, DOCX) or pastes text via the Portal UI, enters matter context, and selects review scope (Responsiveness, Privilege, Key Documents, Hot Documents).
  2. The browser extracts text content and sends it to the API Proxy.
  3. The API Proxy forwards the request (with authentication) to the NAI chat completions endpoint.
  4. NAI analyzes documents and returns structured JSON with classification, relevance scores, privilege flags, themes, summaries, and recommendations.
  5. The Portal UI renders the results: dashboard stats, document classification cards, thematic analysis, and review metrics.
  6. Review metadata is saved to PostgreSQL for audit and history tracking.
  7. Document embeddings are stored in ChromaDB for future conceptual search and TAR workflows.
