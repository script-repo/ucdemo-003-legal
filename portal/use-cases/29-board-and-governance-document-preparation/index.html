Board & Governance Documents

What This Does

Board & Governance Documents uses AI to generate formal board resolutions, meeting minutes, committee charters, bylaws amendments, and consent actions from a simple form. The corporate secretary enters the document type, company name, meeting date, attendees, agenda items, and key decisions — and the AI produces a professionally formatted document with consistent structure, compliance notes, and actionable follow-up items.

Instead of manually drafting each governance document from scratch, the system delivers a ready-to-review draft in seconds.

Example User Journey

1
Complete the Form

The corporate secretary selects the document type (e.g., Meeting Minutes), enters the company name, meeting date, attendees, agenda items, and key decisions.

2
AI Generates

The system sends the form data to the Nutanix AI inference endpoint, which produces a structured governance document in formal language.

3
Review Results

The generated document appears with a formatted body, attendance summary, action items, compliance notes, and next steps.

4
Circulate & Approve

The secretary reviews, edits, and circulates the draft for board approval. Documents are stored for audit and history.

Data Flow Summary

  1. User completes the governance document form (document type, company, date, attendees, agenda, decisions) in the Portal UI.
  2. The browser sends the form data to the API Proxy.
  3. The API Proxy forwards the request (with authentication) to the NAI chat completions endpoint.
  4. NAI generates the governance document and returns a structured JSON response with document text, attendees, action items, compliance notes, and next steps.
  5. The Portal UI renders the results: formatted document, attendance summary, action items list, and compliance notes.
  6. Document metadata is saved to PostgreSQL for audit and history tracking.

Architecture Overview

How It Works

Platform Infrastructure

The entire solution runs on Nutanix AHV, a secure enterprise-grade hypervisor that provides the virtualization layer for all compute, storage, and networking. On top of AHV, NKP (Nutanix Kubernetes Platform) provisions and manages the Kubernetes environment, providing container orchestration, auto-scaling, service discovery, and lifecycle management for all application workloads.

Kubernetes Workloads (db-project-003 namespace)

All use-case components are deployed as pods within the db-project-003 Kubernetes namespace:

  • Portal UI — A lightweight static front-end (HTML, CSS, JavaScript) that provides the governance document form, architecture visualization, and results display. Served by a Python-based development server that also acts as the API proxy.
  • API Proxy (server.py) — A server-side CORS proxy that routes browser requests to the Nutanix AI endpoints. Because the NAI inference service does not return browser CORS headers, all /api/ai/* requests are forwarded server-side with the bearer token injected, eliminating cross-origin restrictions.
  • PostgreSQL 16 (pg-db) — A relational database that stores document metadata, audit logs, and user activity. Exposed internally via ClusterIP on port 5432. Data is persisted on a Nutanix Volumes PVC (20 GiB) to ensure durability across pod restarts and rescheduling.
  • ChromaDB (ch-db) — An open-source vector database used as the RAG (Retrieval-Augmented Generation) store for clause embeddings. Exposed internally via ClusterIP on port 8000 with its own Nutanix Volumes PVC (20 GiB).
  • Ingress / LoadBalancer Service — External traffic is routed into the cluster via a Kubernetes LoadBalancer service, providing a stable IP address for browser access without requiring DNS configuration.

AI & Inference (Nutanix AI — NAI)

Nutanix AI (NAI) provides the enterprise inference endpoints that power the governance document generation:

  • Chat Completions (llama3-1-8b) — The primary LLM endpoint. When a form is submitted, the document type, company name, meeting date, attendees, agenda items, and key decisions are sent along with a structured system prompt that instructs the model to return a JSON object containing the full document text, attendees, action items, compliance notes, and next steps.

Storage Layer

  • Nutanix Unified Storage — Serves as the model repository for NAI, hosting the LLM weights, tokenizer configurations, and model artifacts for both the chat completions model (llama3-1-8b) and the embedding model (llama-3-2-embed).
  • Nutanix Volumes — Provides persistent block storage for the Kubernetes PVCs backing PostgreSQL and ChromaDB. Volumes ensures data durability, snapshots, and consistent performance for database workloads running as containerized pods on NKP.
