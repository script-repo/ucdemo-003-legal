Client Communication

What This Does

Client Communication generates professional client communications from matter data. Enter client name, matter title, recent activity, and deadlines. Select the communication type (Status Update, Deadline Reminder, Case Summary, or Next Steps) and tone. The AI drafts a polished, ready-to-send email or letter that keeps clients informed without attorney time on boilerplate.

Use this for routine status updates, deadline reminders, case summaries, and next-steps correspondence. The system produces consistent, clear, plain-language communications that attorneys can review and send with minimal edits.

Example User Journey

1
Enter Matter Details

Enter the client name, matter title, recent activity or milestones, and any upcoming deadlines. Provide the context the AI needs to draft an accurate update.

2
Select Communication Type

Choose Status Update, Deadline Reminder, Case Summary, or Next Steps. Optionally select tone: Formal, Friendly, or Urgent.

3
AI Generates Draft

The system sends the matter data to the Nutanix AI inference endpoint and receives a professionally formatted communication with subject line, body text, and key points.

4
Review and Send

Review the draft in the email-style preview. Copy to your email client or export. Make any edits and send to the client.

Data Flow Summary

  1. User enters matter details (client name, matter title, recent activity, deadlines) and selects communication type via the Portal UI.
  2. The browser sends the form data to the API Proxy.
  3. The API Proxy forwards the request (with authentication) to the NAI chat completions endpoint.
  4. NAI generates a structured JSON response with subject, body, key points, tone, and suggested follow-up.
  5. The Portal UI renders the results: email-style preview, tone badge, key points summary.
  6. Communication metadata is saved to PostgreSQL for audit and history tracking.

Architecture Overview

How It Works

Platform Infrastructure

The entire solution runs on Nutanix AHV, a secure enterprise-grade hypervisor that provides the virtualization layer for all compute, storage, and networking. On top of AHV, NKP (Nutanix Kubernetes Platform) provisions and manages the Kubernetes environment, providing container orchestration, auto-scaling, service discovery, and lifecycle management for all application workloads.

Kubernetes Workloads (db-project-003 namespace)

All use-case components are deployed as pods within the db-project-003 Kubernetes namespace:

  • Portal UI — A lightweight static front-end (HTML, CSS, JavaScript) that provides the client communication form, architecture visualization, and results display. Served by a Python-based development server that also acts as the API proxy.
  • API Proxy (server.py) — A server-side CORS proxy that routes browser requests to the Nutanix AI endpoints. Because the NAI inference service does not return browser CORS headers, all /api/ai/* requests are forwarded server-side with the bearer token injected, eliminating cross-origin restrictions.
  • PostgreSQL 16 (pg-db) — A relational database that stores communication metadata, audit logs, and user activity. Exposed internally via ClusterIP on port 5432. Data is persisted on a Nutanix Volumes PVC (20 GiB) to ensure durability across pod restarts and rescheduling.
  • ChromaDB (ch-db) — An open-source vector database used as the RAG (Retrieval-Augmented Generation) store for clause embeddings. Exposed internally via ClusterIP on port 8000 with its own Nutanix Volumes PVC (20 GiB).
  • Ingress / LoadBalancer Service — External traffic is routed into the cluster via a Kubernetes LoadBalancer service, providing a stable IP address for browser access without requiring DNS configuration.

AI & Inference (Nutanix AI — NAI)

Nutanix AI (NAI) provides the enterprise inference endpoints that power client communication drafting:

  • Chat Completions (llama3-1-8b) — The primary LLM endpoint. When matter data is submitted, the form content is sent along with a structured system prompt that instructs the model to return a JSON object containing subject line, body text, key points, tone, and suggested follow-up. The model produces professional legal communications tailored to the selected type and tone.

Storage Layer

  • Nutanix Unified Storage — Serves as the model repository for NAI, hosting the LLM weights and model artifacts.
  • Nutanix Volumes — Provides persistent block storage for the Kubernetes PVCs backing PostgreSQL and ChromaDB.
