Contract Redlining & Clause Comparison

Architecture Overview

How It Works

Platform Infrastructure

The entire solution runs on Nutanix AHV, a secure enterprise-grade hypervisor that provides the virtualization layer for all compute, storage, and networking. On top of AHV, NKP (Nutanix Kubernetes Platform) provisions and manages the Kubernetes environment, providing container orchestration, auto-scaling, service discovery, and lifecycle management for all application workloads.

Kubernetes Workloads (db-project-003 namespace)

All use-case components are deployed as pods within the db-project-003 Kubernetes namespace:

  • Portal UI — A lightweight static front-end (HTML, CSS, JavaScript) that provides the dual-document upload interface (counterparty draft + firm standard), architecture visualization, and redline comparison results. Served by a Python-based development server that also acts as the API proxy.
  • API Proxy (server.py) — A server-side CORS proxy that routes browser requests to the Nutanix AI endpoints. Because the NAI inference service does not return browser CORS headers, all /api/ai/* requests are forwarded server-side with the bearer token injected, eliminating cross-origin restrictions.
  • PostgreSQL 16 (pg-db) — A relational database that stores contract metadata, comparison results, audit logs, and user activity. Exposed internally via ClusterIP on port 5432. Data is persisted on a Nutanix Volumes PVC (20 GiB) to ensure durability across pod restarts and rescheduling.
  • ChromaDB (ch-db) — An open-source vector database used as the RAG (Retrieval-Augmented Generation) store for clause embeddings. Contract clauses from both counterparty draft and firm standard are vectorized using the NAI embedding model and stored in ChromaDB for fast similarity search and clause alignment. Exposed internally via ClusterIP on port 8000 with its own Nutanix Volumes PVC (20 GiB).
  • Ingress / LoadBalancer Service — External traffic is routed into the cluster via a Kubernetes LoadBalancer service, providing a stable IP address for browser access without requiring DNS configuration.

AI & Inference (Nutanix AI — NAI)

Nutanix AI (NAI) provides the enterprise inference endpoints that power the contract redlining and clause comparison:

  • Chat Completions (llama3-1-8b) — The primary LLM endpoint for clause comparison and redline generation. When both documents are uploaded (counterparty draft and firm standard), the full texts are sent along with a structured system prompt that instructs the model to return a JSON object containing the risk score, clause-by-clause comparison with redline markup, deviation analysis, severity badges, suggested language, missing/added clauses, and overall recommendations. The model performs legal reasoning to identify non-standard terms, assess severity, and generate actionable redline suggestions.
  • Embeddings (llama-3-2-embed) — The embedding model vectorizes contract clauses from both documents into high-dimensional vectors. These vectors are stored in ChromaDB and used for semantic search and clause alignment—enabling the RAG pipeline to match counterparty clauses to firm standard clauses for accurate comparative analysis.

RAG Pipeline for Clause Alignment

The Retrieval-Augmented Generation pipeline for redlining works as follows:

  1. Clause Embedding — Clauses from both the counterparty draft and firm standard are sent to the NAI embedding endpoint (llama-3-2-embed), which returns vector representations for each clause.
  2. Vector Search & Alignment — Embedding vectors are queried against ChromaDB's clause collection to find semantically similar clauses across the two documents, enabling automatic clause-to-clause alignment.
  3. Context Assembly — Retrieved clauses, their metadata, and alignment results are assembled as context for the LLM.
  4. LLM Redline Analysis — Both document texts, retrieved context, and system prompt are sent to the NAI chat completions endpoint (llama3-1-8b), which produces the comparison with redline markup, deviation detection, severity ratings, and suggested language.

Storage Layer

  • Nutanix Unified Storage — Serves as the model repository for NAI, hosting the LLM weights, tokenizer configurations, and model artifacts for both the chat completions model (llama3-1-8b) and the embedding model (llama-3-2-embed). This ensures model data resides on-prem with enterprise-grade data protection, deduplication, and replication.
  • Nutanix Volumes — Provides persistent block storage for the Kubernetes PVCs backing PostgreSQL and ChromaDB. Volumes ensures data durability, snapshots, and consistent performance for database workloads running as containerized pods on NKP.

Data Flow Summary

  1. User uploads or pastes two documents: counterparty draft and firm standard (TXT, PDF, DOCX).
  2. The browser extracts text content from both documents and sends them to the API Proxy.
  3. The API Proxy forwards the request (with authentication) to the NAI chat completions endpoint.
  4. NAI analyzes both documents and returns a structured JSON response with risk scores, clause-by-clause comparison, redline markup, deviations, and recommendations.
  5. The Portal UI renders the results: summary stats, risk assessment, clause comparison cards with redline styling, missing/added clauses, and recommendations.
  6. Comparison metadata is saved to PostgreSQL for audit and history tracking.
  7. Clause embeddings are stored in ChromaDB for future RAG-powered comparative analysis.
