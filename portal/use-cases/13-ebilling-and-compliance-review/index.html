E-Billing & Compliance Review

What This Does

E-Billing & Compliance Review uses AI to automatically review legal invoices and billing narratives for compliance with billing guidelines. Instead of manually checking every line item against firm policies, the system delivers a structured breakdown in seconds: an overall compliance score (1–100), a line-by-line analysis showing status and issues, and actionable recommendations for every flagged entry.

Upload an invoice (PDF, TXT, or DOCX) or paste invoice text directly. The AI flags non-compliant entries, block billing, vague descriptions, rate violations, and other guideline deviations — all presented in a clear, structured format that billing coordinators and legal ops can review and act on before submission.

Example User Journey

A billing coordinator receives an outside counsel invoice. She drags the PDF into the upload zone — or pastes the invoice text directly.

2
AI Analyzes

The system extracts the text, sends it to the Nutanix AI inference endpoint, and receives a structured compliance analysis in seconds.

3
Review Results

A compliance score of 72 / Needs Review appears. The line-item table shows entries flagged for vague descriptions, block billing, or rate violations. Rejected items are clearly marked.

4

For each flagged entry, the AI provides specific recommendations. The billing coordinator shares feedback with outside counsel — reducing rework and improving first-pass acceptance.

Data Flow Summary

  1. User uploads an invoice document (TXT, PDF, DOCX) or pastes invoice text via the Portal UI.
  2. The browser extracts the text content and sends it to the API Proxy.
  3. The API Proxy forwards the request (with authentication) to the NAI chat completions endpoint.
  4. NAI analyzes the invoice and returns a structured JSON response with compliance scores, line items, and flags.
  5. The Portal UI renders the results: compliance score badge, summary, line-item table, flagged items, and recommendations.
  6. Invoice metadata is saved to PostgreSQL for audit and history tracking.
  7. Invoice embeddings are stored in ChromaDB for future RAG-powered comparative analysis.

Architecture Overview

How It Works

Platform Infrastructure

The entire solution runs on Nutanix AHV, a secure enterprise-grade hypervisor that provides the virtualization layer for all compute, storage, and networking. On top of AHV, NKP (Nutanix Kubernetes Platform) provisions and manages the Kubernetes environment, providing container orchestration, auto-scaling, service discovery, and lifecycle management for all application workloads.

Kubernetes Workloads (db-project-003 namespace)

All use-case components are deployed as pods within the db-project-003 Kubernetes namespace:

  • Portal UI — A lightweight static front-end (HTML, CSS, JavaScript) that provides the invoice upload interface, architecture visualization, and compliance results display. Served by a Python-based development server that also acts as the API proxy.
  • API Proxy (server.py) — A server-side CORS proxy that routes browser requests to the Nutanix AI endpoints. Because the NAI inference service does not return browser CORS headers, all /api/ai/* requests are forwarded server-side with the bearer token injected, eliminating cross-origin restrictions.
  • PostgreSQL 16 (pg-db) — A relational database that stores invoice metadata, compliance results, audit logs, and user activity. Exposed internally via ClusterIP on port 5432. Data is persisted on a Nutanix Volumes PVC (20 GiB) to ensure durability across pod restarts and rescheduling.
  • ChromaDB (ch-db) — An open-source vector database used as the RAG (Retrieval-Augmented Generation) store for invoice embeddings. Invoice line items are vectorized using the NAI embedding model and stored in ChromaDB for fast similarity search. Exposed internally via ClusterIP on port 8000 with its own Nutanix Volumes PVC (20 GiB).
  • Ingress / LoadBalancer Service — External traffic is routed into the cluster via a Kubernetes LoadBalancer service, providing a stable IP address for browser access without requiring DNS configuration.

AI & Inference (Nutanix AI — NAI)

Nutanix AI (NAI) provides the enterprise inference endpoints that power the invoice compliance analysis:

  • Chat Completions (llama3-1-8b) — The primary LLM endpoint. When an invoice is uploaded, the full text is sent along with a structured system prompt that instructs the model to return a JSON object containing the compliance score, compliance level, line-by-line analysis, flagged items, and recommendations. The model performs legal billing reasoning to identify non-compliant entries, block billing, vague descriptions, rate violations, and generate actionable recommendations.
  • Embeddings (llama-3-2-embed) — The embedding model vectorizes invoice line items and user queries into high-dimensional vectors. These vectors are stored in ChromaDB and used for semantic search—enabling the RAG pipeline to retrieve relevant billing guideline examples when performing comparative analysis.

RAG Pipeline

The Retrieval-Augmented Generation pipeline works as follows:

  1. Query Embedding — The user's invoice text is sent to the NAI embedding endpoint (llama-3-2-embed), which returns a vector representation.
  2. Vector Search — The embedding vector is queried against ChromaDB to find the most semantically similar billing entries from the firm's guideline library.
  3. Context Assembly — Retrieved entries and their metadata are assembled as context for the LLM.
  4. LLM Analysis — The invoice text, retrieved context, and system prompt are sent to the NAI chat completions endpoint (llama3-1-8b), which produces the final compliance analysis with scoring, line-item classification, and flag recommendations.

Storage Layer

  • Nutanix Unified Storage — Serves as the model repository for NAI, hosting the LLM weights, tokenizer configurations, and model artifacts for both the chat completions model (llama3-1-8b) and the embedding model (llama-3-2-embed). This ensures model data resides on-prem with enterprise-grade data protection, deduplication, and replication.
  • Nutanix Volumes — Provides persistent block storage for the Kubernetes PVCs backing PostgreSQL and ChromaDB. Volumes ensures data durability, snapshots, and consistent performance for database workloads running as containerized pods on NKP.
