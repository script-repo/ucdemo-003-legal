Deposition & Transcript Analysis

What This Does

Deposition & Transcript Analysis uses AI to automatically read deposition or hearing transcripts, extract key testimony, identify contradictions, and produce structured summaries. Instead of spending hours combing through hundreds of pages, the system delivers a witness summary, key testimony cards with quotes and significance, a list of contradictions (Minor, Significant, or Critical), suggested follow-up questions for cross-examination, and a timeline of events — all in seconds.

Upload a transcript (TXT, PDF, DOCX) or paste the text directly. The AI identifies damaging testimony, inconsistent statements, credibility concerns, and critical admissions. Trial counsel can use the output for prep, motions, and cross-examination planning.

Example User Journey

1
Upload Transcript

An associate receives a deposition transcript from the court reporter. She drags the PDF into the upload zone — or pastes the text directly.

2
AI Analyzes

The system extracts the text, sends it to the Nutanix AI inference endpoint, and receives a structured analysis: witness summary, key testimony, contradictions, and suggested questions.

3
Review Findings

The witness summary and key testimony cards appear. Contradictions are flagged by severity. Suggested follow-up questions and a timeline of events help the trial team prepare for cross-examination.

4
Export

The team copies key quotes, contradictions, and questions into trial prep materials. Analysis is saved to history for quick recall. Export or share as needed for motions and trial.

Data Flow Summary

  1. User uploads a transcript document (TXT, PDF, DOCX) or pastes transcript text via the Portal UI.
  2. The browser extracts the text content and sends it to the API Proxy.
  3. The API Proxy forwards the request (with authentication) to the NAI chat completions endpoint.
  4. NAI analyzes the transcript and returns a structured JSON response with witness summary, key testimony, contradictions, suggested questions, and timeline.
  5. The Portal UI renders the results: witness summary, testimony cards, contradictions list, follow-up questions, and timeline of events.
  6. Analysis metadata is saved to PostgreSQL for audit and history tracking.

Architecture Overview

How It Works

Platform Infrastructure

The entire solution runs on Nutanix AHV, a secure enterprise-grade hypervisor that provides the virtualization layer for all compute, storage, and networking. On top of AHV, NKP (Nutanix Kubernetes Platform) provisions and manages the Kubernetes environment, providing container orchestration, auto-scaling, service discovery, and lifecycle management for all application workloads.

Kubernetes Workloads (db-project-003 namespace)

All use-case components are deployed as pods within the db-project-003 Kubernetes namespace:

  • Portal UI — A lightweight static front-end (HTML, CSS, JavaScript) that provides the transcript upload interface, architecture visualization, and analysis results display. Served by a Python-based development server that also acts as the API proxy.
  • API Proxy (server.py) — A server-side CORS proxy that routes browser requests to the Nutanix AI endpoints. Because the NAI inference service does not return browser CORS headers, all /api/ai/* requests are forwarded server-side with the bearer token injected, eliminating cross-origin restrictions.
  • PostgreSQL 16 (pg-db) — A relational database that stores transcript analysis metadata, audit logs, and user activity. Exposed internally via ClusterIP on port 5432. Data is persisted on a Nutanix Volumes PVC (20 GiB) to ensure durability across pod restarts and rescheduling.
  • ChromaDB (ch-db) — An open-source vector database used as the RAG (Retrieval-Augmented Generation) store for testimony embeddings. Transcript excerpts are vectorized using the NAI embedding model and stored in ChromaDB for fast similarity search. Exposed internally via ClusterIP on port 8000 with its own Nutanix Volumes PVC (20 GiB).
  • Ingress / LoadBalancer Service — External traffic is routed into the cluster via a Kubernetes LoadBalancer service, providing a stable IP address for browser access without requiring DNS configuration.

AI & Inference (Nutanix AI — NAI)

Nutanix AI (NAI) provides the enterprise inference endpoints that power the transcript analysis:

  • Chat Completions (llama3-1-8b) — The primary LLM endpoint. When a transcript is uploaded, the full text is sent along with a structured system prompt that instructs the model to return a JSON object containing the witness name, summary, key testimony, contradictions, suggested follow-up questions, timeline of events, and credibility notes. The model performs legal reasoning to identify damaging testimony, inconsistent statements, and cross-examination opportunities.
  • Embeddings (llama-3-2-embed) — The embedding model vectorizes transcript excerpts and user queries into high-dimensional vectors. These vectors are stored in ChromaDB and used for semantic search—enabling the RAG pipeline to retrieve the most relevant testimony when performing comparative analysis across depositions.

Storage Layer

  • Nutanix Unified Storage — Serves as the model repository for NAI, hosting the LLM weights, tokenizer configurations, and model artifacts for both the chat completions model (llama3-1-8b) and the embedding model (llama-3-2-embed).
  • Nutanix Volumes — Provides persistent block storage for the Kubernetes PVCs backing PostgreSQL and ChromaDB. Volumes ensures data durability, snapshots, and consistent performance for database workloads running as containerized pods on NKP.
