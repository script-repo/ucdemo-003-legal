Document Drafting

What This Does

Document Drafting uses AI to generate first drafts of NDAs, engagement letters, and routine notices from matter context and firm templates. Instead of starting from scratch or hunting through precedent, you enter key variables — document type, party names, matter description, key dates, and special terms — and the system produces a professional first draft in seconds.

Select an NDA, engagement letter, or notice template. Provide the parties, matter details, and any custom terms. The AI generates a complete draft with consistent language, flags non-standard terms for review, and surfaces key terms in a summary. Associates and paralegals save hours per document while maintaining quality and compliance.

Example User Journey

1
Select Document Type & Enter Context

An attorney selects "NDA" from the dropdown, enters disclosing and receiving party names, describes the deal type, adds key dates, and optionally specifies special terms (e.g., carve-outs, term length).

2
AI Generates Draft

The system sends the form data to the Nutanix AI inference endpoint. The model produces a complete first draft using standard legal language and the provided variables.

3
Review Draft & Key Terms

The full draft appears in a formatted display. A key terms summary shows party names, dates, and other extracted variables. Any non-standard items are flagged in the warnings section.

4
Edit & Send

The attorney or paralegal reviews, makes edits, and sends for signature or delivery. The draft is saved to history for audit and reuse.

Data Flow Summary

  1. User selects document type and enters party names, matter description, key dates, and special terms via the Portal UI form.
  2. The browser sends the form data to the API Proxy.
  3. The API Proxy forwards the request (with authentication) to the NAI chat completions endpoint.
  4. NAI generates the document draft and returns a structured JSON response with the draft text, key terms, and warnings.
  5. The Portal UI renders the results: document display, key terms summary, and warnings.
  6. Draft metadata is saved to PostgreSQL for audit and history tracking.
  7. Clause embeddings may be stored in ChromaDB for future RAG-powered precedent retrieval.

Architecture Overview

How It Works

Platform Infrastructure

The entire solution runs on Nutanix AHV, a secure enterprise-grade hypervisor that provides the virtualization layer for all compute, storage, and networking. On top of AHV, NKP (Nutanix Kubernetes Platform) provisions and manages the Kubernetes environment, providing container orchestration, auto-scaling, service discovery, and lifecycle management for all application workloads.

Kubernetes Workloads (ntnx-use-cases namespace)

All use-case components are deployed as pods within the ntnx-use-cases Kubernetes namespace:

  • Portal UI — A lightweight static front-end (HTML, CSS, JavaScript) that provides the document drafting form, architecture visualization, and draft results display. Served by a Python-based development server that also acts as the API proxy.
  • API Proxy (server.py) — A server-side CORS proxy that routes browser requests to the Nutanix AI endpoints. Because the NAI inference service does not return browser CORS headers, all /api/ai/* requests are forwarded server-side with the bearer token injected, eliminating cross-origin restrictions.
  • PostgreSQL 16 (pg-db) — A relational database that stores draft metadata, key terms, audit logs, and user activity. Exposed internally via ClusterIP on port 5432. Data is persisted on a Nutanix Volumes PVC (20 GiB) to ensure durability across pod restarts and rescheduling.
  • ChromaDB (ch-db) — An open-source vector database used as the RAG (Retrieval-Augmented Generation) store for clause embeddings. Document clauses may be vectorized using the NAI embedding model and stored in ChromaDB for precedent retrieval. Exposed internally via ClusterIP on port 8000 with its own Nutanix Volumes PVC (20 GiB).
  • Ingress / LoadBalancer Service — External traffic is routed into the cluster via a Kubernetes LoadBalancer service, providing a stable IP address for browser access without requiring DNS configuration.

AI & Inference (Nutanix AI — NAI)

Nutanix AI (NAI) provides the enterprise inference endpoints that power document drafting:

  • Chat Completions (llama3-1-8b) — The primary LLM endpoint. When form data is submitted, the document type, party names, matter description, dates, and special terms are sent along with a structured system prompt that instructs the model to return a JSON object containing the draft text, title, key terms, and warnings. The model generates professional legal documents using standard language and the provided variables.
  • Embeddings (llama-3-2-embed) — The embedding model vectorizes document clauses and precedent for semantic search. These vectors are stored in ChromaDB and used for RAG—enabling retrieval of relevant precedent when generating drafts.

Storage Layer

  • Nutanix Unified Storage — Serves as the model repository for NAI, hosting the LLM weights, tokenizer configurations, and model artifacts for both the chat completions model (llama3-1-8b) and the embedding model (llama-3-2-embed). This ensures model data resides on-prem with enterprise-grade data protection, deduplication, and replication.
  • Nutanix Volumes — Provides persistent block storage for the Kubernetes PVCs backing PostgreSQL and ChromaDB. Volumes ensures data durability, snapshots, and consistent performance for database workloads running as containerized pods on NKP.
