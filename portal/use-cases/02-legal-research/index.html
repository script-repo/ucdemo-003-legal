Legal Research

What This Does

Legal Research uses AI-powered semantic search and retrieval-augmented generation (RAG) to answer natural-language legal questions. Instead of manually searching through databases of case law, statutes, and regulations, an attorney types a question in plain English and receives a structured answer with ranked authorities, citations, relevance scores, and key passages — in seconds.

The system searches a vectorized corpus of legal documents stored in ChromaDB, retrieves the most semantically relevant authorities, and sends them as context to the LLM. The result is a research memo-style response with primary authorities, contrary authority, and suggested follow-up questions — all backed by specific citations that the attorney can verify.

Example User Journey

1
Ask a Question

A litigation associate needs to know the elements of breach of fiduciary duty in Delaware. She types: "What are the elements of breach of fiduciary duty in Delaware?"

2
AI Searches & Reasons

The system vectorizes the query, searches ChromaDB for relevant case law and statutes, assembles the most relevant authorities as context, and sends everything to the LLM for structured analysis.

3
Review Authorities

Results appear as ranked authority cards: Guth v. Loft, Inc. (Del. 1939) at 95% relevance, Cede & Co. v. Technicolor (Del. 1993) at 88% relevance. Each card shows the citation, jurisdiction, a key passage, and a relevance score. Contrary authority is listed separately.

4
Refine & Continue

The system suggests follow-up questions like "How does the business judgment rule interact with fiduciary duty in Delaware?" The associate clicks one to deepen her research — building a complete analysis in minutes instead of hours.

Data Flow Summary

  1. Attorney enters a natural-language legal research question via the Portal UI.
  2. The browser sends the query to the API Proxy.
  3. The API Proxy forwards the request (with authentication) to the NAI embedding endpoint to vectorize the query.
  4. The proxy (or backend service) queries ChromaDB for semantically similar legal documents.
  5. Retrieved context is assembled and sent with the original query to the NAI chat completions endpoint.
  6. NAI returns a structured JSON response with summary, authorities, contrary authority, and follow-up suggestions.
  7. The Portal UI renders the results: authority cards with citations, summaries, relevance scores, and feedback buttons.
  8. Research history is saved to PostgreSQL for audit and history tracking.

Architecture Overview

How It Works

Platform Infrastructure

The entire solution runs on Nutanix AHV, a secure enterprise-grade hypervisor that provides the virtualization layer for all compute, storage, and networking. On top of AHV, NKP (Nutanix Kubernetes Platform) provisions and manages the Kubernetes environment, providing container orchestration, auto-scaling, service discovery, and lifecycle management for all application workloads. NKP runs on AHV.

Kubernetes Workloads (db-project-003 namespace)

All use-case components are deployed as pods within the db-project-003 Kubernetes namespace:

  • Portal UI — A lightweight static front-end (HTML, CSS, JavaScript) that provides the Legal Research page, architecture visualization, and results display. Served by a Python-based development server that also acts as the API proxy.
  • API Proxy (server.py) — A server-side CORS proxy that routes browser requests to the Nutanix AI endpoints. Because the NAI inference service does not return browser CORS headers, all /api/ai/* requests are forwarded server-side with the bearer token injected, eliminating cross-origin restrictions.
  • PostgreSQL (pg-db) — A relational database that stores research queries, history, and audit logs. Exposed internally via ClusterIP on port 5432. Data is persisted on a Nutanix Volumes PVC (20 GiB) to ensure durability across pod restarts and rescheduling.
  • ChromaDB (ch-db) — An open-source vector database used as the RAG store for legal document embeddings. Legal cases, statutes, and secondary sources are vectorized using the NAI embedding model (llama-3-2-embed) and stored in ChromaDB for fast semantic search. Exposed internally via ClusterIP on port 8000 with its own Nutanix Volumes PVC (20 GiB).
  • Ingress / LoadBalancer Service — External traffic is routed into the cluster via a Kubernetes LoadBalancer service, providing a stable IP address for browser access without requiring DNS configuration.

AI & Inference (Nutanix AI — NAI)

Nutanix AI (NAI) provides the enterprise inference endpoints that power legal research:

  • Chat Completions (llama3-1-8b) — The primary LLM endpoint. When an attorney enters a natural-language research question, the query (along with retrieved context from ChromaDB) is sent to the chat completions endpoint. The model performs legal reasoning to generate a structured answer with a summary, ranked authorities (cases, statutes, secondary sources), contrary authority, and suggested follow-up questions. The system prompt instructs the model to return JSON with citations, jurisdictions, relevance scores, and key passages.
  • Embeddings (llama-3-2-embed) — The NAI embedding model vectorizes legal documents and user queries into high-dimensional vectors. These vectors are stored in ChromaDB and used for semantic search—enabling the RAG pipeline to retrieve the most relevant legal authorities from the firm's corpus when answering research questions.

RAG Pipeline for Legal Research

The Retrieval-Augmented Generation pipeline works as follows:

  1. Query Embedding — The user's natural-language research question is sent to the NAI embedding endpoint (llama-3-2-embed), which returns a vector representation.
  2. Vector Search — The embedding vector is queried against ChromaDB's legal document collection to find the most semantically similar cases, statutes, and secondary sources.
  3. Context Assembly — Retrieved authorities and their metadata (citations, jurisdictions, summaries) are assembled as context for the LLM.
  4. LLM Answer Generation — The research question, retrieved context, and system prompt are sent to the NAI chat completions endpoint (llama3-1-8b), which produces a structured JSON response with a summary, ranked authorities, contrary authority, and suggested follow-up questions.

Storage Layer

  • Nutanix Unified Storage — Provides the LLM model repository for NAI, hosting the model weights, tokenizer configurations, and model artifacts for both the chat completions model (llama3-1-8b) and the embedding model (llama-3-2-embed). This ensures model data resides on-prem with enterprise-grade data protection, deduplication, and replication.
  • Nutanix Volumes — Provides persistent block storage for the Kubernetes PVCs backing PostgreSQL and ChromaDB. Volumes ensures data durability, snapshots, and consistent performance for database workloads running as containerized pods on NKP.
